推荐结论

  • 选择 A 作为目标架构：共享 domain rail、entity directory、detail inspector。
  • 保留现有 V4 API 和 panel 数据加载边界，先重组信息展示，不扩 backend scope。
  • Quality 不是隐藏诊断页，而是控制台里的治理队列：隔离、发现、修正、重处理。
  • Raw claim / id / provenance 可检查，但不作为默认第一阅读层。

需要你定的点

  • 是否确认 A 作为设计方向？
  • Domain 入口用左侧竖 rail，还是保留顶部 tabs 但进入后采用目录+检查器？
  • Quality 是否固定为最后一个治理入口，还是在总览里也给强提示？
